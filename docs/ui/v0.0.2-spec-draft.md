## Spec issue: `v0.0.2: Beautiful` (label `spec`)

**lobotomy is Qwen running on my Coralboard so you can watch its neurons light up as it talks, and later push them.**

v0.0.2 makes it beautiful: the real UI from the UI grill. Design, decisions and mockups: [docs/ui/design.md](https://github.com/jparker2006/lobotomy/blob/main/docs/ui/design.md).

### What you do
Open `localhost:8000` (served by the board or the CPU stand-in). A deck of 28 layers, 86,016 amber dots, sits in the dark. Type a question. Each word sweeps through the layers in the board's real order and pace, the rarest firings blaze, and the answer runs as subtitles. Hover a dot to read that neuron; click to lock on. `c` opens the console panels, `~` the tuning knobs.

### In scope
- The page in `web/`: TypeScript + three.js r186 (`WebGPURenderer` + TSL, WebGL2 fallback), replacing T2's plain grid (which moves to `/plain.html` as a debug view). Same T2 protocol, no server change.
- Everything in design.md: the deck, two grids (5 × 8 dots, 9 × 16 text), the rarity ladder with the crowding correction, mono amber with filled/ring sign, the astrophage pass (a wide haze from top-1% dots only, depth haze on the lattice, a scrim behind the subtitles), trails, sweep, idle drift, Cinema + Console, hover + lock-on + `/`, the tuning console, record/replay, hero mode C.
- Bundled fonts (JetBrains Mono, Departure Mono; OFL) and three.js, so the board serves the page offline.
- New dependencies: `three` and `@types/three` (types, dev only). No bundler: `tsc` plus an import map. Unit tests run on Node's built-in `node --test`.

### Out of scope
Lens words (v0.0.3). Atlas labels, real-or-not, sliders and layout (v0.1.0): only their grey slots. The board itself (T1–T9). The Blender clip (R14). Server changes.

### Limits
256-token context. Index order inside a sheet is arbitrary until R9. The real hero clip needs board data (T8), and any power wording on it needs R12's measurement. Until then the clip renders from the CPU stand-in with an honest card.

### Done when
- [ ] 1. **E6, smooth.** On Jake's MacBook Air (Mac16,13), Safari 26 and Chrome, full window, native resolution, bloom and trails on, 60 s of live stream: p95 frame time ≤ 16.7 ms and ≤ 1% of frames over 33 ms.
- [ ] 2. **Looks like the grill.** Jake signs off the live page against design.md (Cinema, Console, lock-on, hero C).
- [ ] 3. **I6, honest.** Every per-element visual input in the code is a data field in design.md's channel table. The crowding test passes: on i.i.d. synthetic data, the share of cells at each level is within ±10% of the single-neuron share at 1, 4, 16 and 64 neurons per cell.
- [ ] 4. **Honest provenance.** The HUD shows the backend from `/api/meta`, and replays say `REPLAY`. The end card never makes a power claim from board data alone: a wattage or J/token appears only when the recording carries a measured R12 record (value, method, date), and it shows that measured number (tested with and without the record, for `cpu` and `npu`).
- [ ] 5. **Hero clip C** renders frame by frame from a recorded session to a 10 s 1080p60 MP4, identical across two renders (frame hashes).
- [ ] 6. **Offline.** With the network off, the page loads from `server/server.py` with fonts, three.js and the rarity table bundled.

### How this issue works
Tickets are the sub-issues, in tracer-bullet order. U1 measures the riskiest part (frame time on Jake's Mac) before anything is built on it, U2 is the thin slice through the real pipeline with live data, U3–U6 fatten it, and U7 is acceptance. This issue closes when every sub-issue is closed and every box is checked. ## U1: Benchmark the render pipeline on Jake's Mac (R11)

Agent, plus Jake for one link (~2 minutes).

A bare page in `web/bench/` (not the product) running the real pipeline: 86,016 neurons on the deck → a compute pass (trail + sweep) → splat into the 5 × 8 dot grid (atomic max + count) → the glyph pass (dot atlas) → bloom at half resolution. It's fed synthetic activations at the real frame size, at 6 and 24 tok/s. It logs frame intervals for 60 s per setting (bloom 1× / 0.5×, DPR 1 / 2) and posts p50/p95/p99 and the share over 33 ms back to a small stdlib server. Jake opens it through a Cloudroom preview in Safari 26 and Chrome.

**Done when:** both browsers report p95 ≤ 16.7 ms and ≤ 1% over 33 ms at native resolution with bloom on. If not, the report names the step that blows the budget and the fallback that fixes it.

**Why first:** E6 is the one external check the UI owns, and this pipeline (WebGPU in Safari 26, atomics, bloom at Retina) is the riskiest part. Measure it before building on it.

**Blocked by:** nothing

## U5: Inspect: hover, lock-on, search, word replay

Agent.

Picking returns the neuron the dot shows (the one that set the cell's max). The hover card shows `L·N`, now ×p99 and rarity, the word and a sparkline. Click locks on: the camera turns the layer face-on, other layers hide, a reticle locks, and the readout docks (fires most on in this answer, plus grey slots: words it pushes (v0.0.3); label, real or not, steer (v0.1.0)). `/` jumps (`L8 908`). Clicking a word in the subtitles or tape pins the map to that token; `space` resumes and `Esc` unlocks. The readout takes an optional typed `NeuronInfo` record, so v0.0.3 and v0.1.0 fill the slots without UI changes.

**Done when:** a scripted browser check on a recorded session (run from the agent's sandbox, not a project dependency) shows `/L8 908` locking onto L8 N908 with readout values equal to the session's, and clicking a word pins that token. Jake signs off against [q8-lock](https://github.com/jparker2006/lobotomy/blob/main/docs/ui/mockups/q8-lock.png).

**Blocked by:** U3

## U6: Record, replay and hero mode C

Agent.

Save a session (T2 frames + meta + calibration + UTC time) to a `.lobo` file, and drop a file to replay it (HUD: `REPLAY · backend · date`). A deterministic clock renders any time `t`. Hero mode `?hero=c&neuron=8:908`: macro on the neuron, lock-on readout of its strongest recent value and word, pull back over ~4 s with layers switching on outward, then the end card with a Voyager-style caption (model · backend · recording time). The card says "CPU stand-in" for `cpu` and "live on the Coralboard NPU" for `npu`; a power figure appears only if the recording carries a measured R12 record, and it shows the measured value. A frame-export script renders 1080p60 PNGs to MP4.

**Done when:** a CPU recording renders a 10 s 1080p60 MP4 that matches [q9-hero-c](https://github.com/jparker2006/lobotomy/blob/main/docs/ui/mockups/q9-hero-c.gif), two renders hash identically frame by frame, and the card test passes for `cpu` and `npu`, each with and without an R12 power record (faked).
